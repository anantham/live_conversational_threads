## Intent and decision

The full goal remains computers-off public creation/exploration, optional Google private storage, Soniox and OpenRouter with spending limits. The reviewed pure request/completion adapter alone is not a hosted producer. Add its Worker integration now, without choosing a model/provider/funding/audience, reading a real key, changing the active Site, or storing/publishing user source/results. This is reversible implementation inside the existing selected stack, not a new provider or deployment decision.

Expose GET /api/cloud/openrouter/status and POST /api/cloud/openrouter/generate. Enabled readiness requires explicit runtime flags and server model/provider/data-policy/audience/key/request/token limits plus the actual D1 admission table. POST requires same-origin processing consent; authenticated mode uses the existing provider-qualified identity resolver, while public mode permits guests. Validate a bounded finalized source before one atomic admission statement and one fixed OpenRouter HTTPS request. Use only the existing strict request and source-owned response-to-.threads contracts. Restrict routing to the explicitly configured provider with fallback disabled and an explicitly configured allow/deny data-collection policy. Browser-supplied model, provider, key or output-token settings never control the upstream request.

The new schema stores random attempt ID, admission timestamp, output-token cap and confirmed completion timestamp only. No identity, IP, source, audio, graph, credential or response body. Lifetime counts never reset or refund; cap at200 attempts per configured lifetime. At most2 unresolved attempts, with10seconds between admissions. Successful validated completion releases concurrency; uncertain failures/cancellation/timeout retain the slot conservatively. There is no operator-reset endpoint in this slice. Polling/history/result persistence is not added.

Input is at most512KiB; full provider response at most2MiB. Bound source-body arrival and upstream response with deadlines; propagate a delivered request abort, cancel readers and remove listeners/timers. No automatic retry. Sanitized responses describe whether an attempt was reserved; never return provider error contents or keys. Returning a valid map does not save it or make it public.

Existing request/token caps are usage bounds, not a guaranteed dollar ceiling. Activation requires an independently verified dedicated non-resetting OpenRouter key allowance, approved provider/data policy and user-visible consent, plus the model and runtime settings. No key/budget is selected by code. Keep both enable and budget-confirmation flags absent in the live version16/environment2 preview.
