## Final proposal clarification after two bounded design reviews

The plan was challenged by independent Google and Anthropic reviews; neither is an implementation approval. Supported specification omissions are incorporated below. Stop broad design-only review here; after the human allowance, the concrete source must implement and independently verify these contracts before any live dispatch.

- Operation states are reserved → dispatching → completed, failed or uncertain. A conditional database transition to dispatching is committed before provider POST. Reservation already consumes its allowance; it is never automatically released, including a crash before POST. After a lost acknowledgement/crash, reserved or dispatching state closes further dispatch until read-only reconciliation; no second POST or key mint is allowed. Explicitly test crash injection before/after reservation, dispatch transition, provider response and receipt write.
- STT has exactly one reserved slot before mint. Lost mint response marks uncertain, retains the reservation and closes the trial; never mint again. Store only actual latest start expiry, non-secret session/attempt identifier and duration cap after acknowledgement. The secret temporary key remains only in the authorized browser connection flow. Never store it in receipt/log/source.
- Effective activation is the intersection of a default-off configuration flag, exact owner/recording and a durable trial deadline. Absolute trial lifetime is at most1500seconds from first reservation; expired/failed/completed/spent singleton cannot be rearmed by refreshing configuration. Check the deadline atomically before every reservation and report the effective closed state after expiry, even if a raw configuration flag was not manually cleared. Explicitly clear the configuration after normal completion/failure when connected. No background job is required for refusal after expiry.
- The STT key admits one stream for at most1260seconds; its60second start expiry only bounds latest opening. Do not promise server-side cancellation/revocation when unsupported. If the browser/cancel notification disappears, the worst permitted STT stream exposure remains the full1260seconds (about$0.042 at current reference pricing), with no additional keys or model dispatch. This bounded exposure is included in the requested allowance.
- Reserve one of28model slots for a deliberate final catch-up: maximum27periodic attempts only while audio is active, then maximum one final attempt on final transcript after any in-flight attempt settles and45second spacing is satisfied. If a periodic request already covers the exact final words, no extra final call is needed. Every reserved/failed/uncertain call counts. Allow up to95seconds for completion inside the1500second overall deadline. Final requests are independent of the Soniox stream's expiry, so no contradiction with the1260second key cap. No retry under another sequence/UUID.
- Existing generation sends utterance text only, not prior generated map history. The 8192 source-token limit is a Soniox-token count and must not be claimed to be the LLM tokenizer count. The128KiB serialized-request gate is an explicit additional trial guard, checked before reservation. Actual20minute serialization/decoding readiness and representative increasing synthetic fixtures must be measured; late size/output rejection remains a documented test-failure risk, not an acceptable passing result. No silent truncation, guessed tokenization or empty fixture pass.
- Closed-gate preflight must verify actual available key/account allowance and existing provider limits through documented server-side read-only endpoints without exposing the key. If sufficient allowance cannot be established, do not dispatch; preserve the proposed allowance and report the concrete balance/permission constraint. No key-limit increase or top-up is inferred. Shared-provider credit consumption remains an explicit consequence the operator accepts for this one run.

No statistical performance guarantee from this one run. Operational continuity, quantitative latency target and final full-coverage acceptance are reported separately.
