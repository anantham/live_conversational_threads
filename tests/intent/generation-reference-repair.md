# Generated reference repair test intent

Context: on 3 November 2026 a 20-minute map from `google/gemini-3.5-flash-lite` was rejected at `hierarchy/parent_missing`. The model declared its idea nodes as `node-idea-intro` and referenced them as `idea-intro`. Strict JSON-schema output cannot enforce that references point at declared ids. The owner chose a deterministic, recorded repair (option A) plus a longer map window (option D).

- A reply whose dangling typed references are all fixed by ONE affix operation (add or strip one delimiter-ended prefix, or one delimiter-led suffix) resolves to the declared nodes and is accepted. This covers parents, secondary parents, edge endpoints and thread moments, and the repair is reported with its operation, affix and count.
- References that already resolve are never changed. A reply with no dangling references reports no repair.
- The repair needs evidence of systematic drift: every declared id at a touched level carries the added affix (none carries a stripped one); within each reference family (parents, edges, thread steps) the references to one level are wholly resolved or wholly dangling (the observed reply: all 20 chunk→idea parents omitted `node-`, all 7 higher parents kept it), so mixed `x`/`node-x` use within a family, or a lone dangling reference among resolved ones, is never repaired, while drifted parents beside edges that already use declared ids still are; beside references that already resolve, no strip operation applies, and either each resolved reference carries the added affix or the drift is a prefix confined to one tier. In that case the drift repeats across at least two distinct targets. Every declared id at the tier is the affix plus its tier word, a delimiter and a name starting with a letter or digit (`node-idea-programming`). Every declared id at every other tier, referenced or not, leads with its tier the same way, and the affix contains no tier word. That second case is the 4 November reply: only the idea tier declared `node-`, two chunks referenced `idea-programming`, and every other tier resolved. So `-2` is never stripped, and a shared word like `non-` on bare names is never added on the strength of two nodes. A one-tier drift is still refused when its ids do not name their tier, when only some do, or when they name another tier. It is also refused when the tier word is only part of a word (`ideas-`), when the prefix sits before a trailing tier word (`non-water-idea`), when a suffix lands on the name (`idea-water-shortage`), when the affix begins with a tier word (`idea-`, `Topic-`, `topic1-`, `ideas-`), or when the name after the tier word is empty (`idea-`, `idea--`). It is also refused when a declared sibling at the tier does not name it once the affix is removed, when only one target drifted (one node, or two references to one node), when the name does not start right after the tier delimiter (`idea--water`, `ideaswater`), when the affix contains a tier word (`1topic-`), and when any declaration at another tier, referenced or not, is bare or carries the prefix. Likewise when the same prefix drifts at two tiers, when a resolved id elsewhere does not name its tier, when it would strip, or when the target is declared at another level. One tier declared bare while every resolved reference carries the prefix is also refused, because nothing is stripped beside resolved references; any malformed reference slot disables the repair; neither the dangling id nor its repaired target is declared at another level; no purely numeric affix (`-2`); no duplicate declarations; only validator-acceptable ids (non-empty, trimmed, ≤158) take part, so stripping can never shrink an overlong or empty id into an accepted one.
- The repair stays strict. If any dangling reference is not fixed by the shared operation, or two different operations would both work, or the affix is not delimiter-bounded (e.g. `top` → `topic`), or the match is at a different level, the reply is rejected exactly as before (same stage and rule). The authored input is never mutated.
- After repair the full validator still runs, so a repair that produces a duplicate or wrong-level link is still rejected.
- Both Worker routes (map `/generate` and the private replay) log every applied repair unconditionally, and `/generate` reports it in the response.
- The map provider window is 90 s. The browser's generate deadline (125 s) exceeds the 30 s input window plus the provider window, so the server's 408 arrives before the client gives up. Synthetic fixtures only; no provider is called.
